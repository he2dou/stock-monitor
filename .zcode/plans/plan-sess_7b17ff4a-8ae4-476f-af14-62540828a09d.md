# SOXL leveraged_breakout_pullback 全面改造计划

## 范围与决策(已确认)
- **深度**: 全部 P0 + P1 + P2
- **仓位基数**: risk_percent 改为按**总权益(equity)**,加可配最小仓位下限
- **趋势跟随变体**: 本次**不做**,只优化现有突破回踩策略
- **新参数取值**: 用合理默认值,配置里标注"待回测校准"
- **数据约束**: `Quote` 只有 close + volume(无 OHLC)。因此 ATR 改用**收盘价波动率近似**,分级止损用显式百分比;若未来把 OHLC 接入 Quote 可升级为真 ATR。所有默认值保持**向后兼容**(老配置不填新字段时行为不变)。

---

## Phase 1 — 数据模型与配置扩展 (`trading_models.py`)

### 1a. `LeveragedBreakoutPullbackSetup` 新增字段(均有默认值,老配置不受影响)
```python
# 更鲁棒的压力位(第8点)
resistance_percentile: float = 100.0      # 100=取max(旧行为); 95=忽略尖峰
# 更强的确认(第9点)
require_close_above_resistance_bars: int = 1  # 1=旧行为; 2=需连续2根收盘站上
# 分级止损(第5点)
trailing_stop_pct_after_partial: float | None = None  # 部分止盈后用更紧的止损(如11%)
time_stop_bars: int | None = None                     # 持仓N根bar未到1R则平仓
cooldown_after_stop_minutes: int = 0                  # 止损离场后冷却(第10点)
# 市场状态/量/RSI过滤(第7点)
require_volume_confirm: bool = False
volume_confirm_mult: float = 1.5           # 突破bar量需 > 近N日均量×mult
volume_avg_period: int = 20
rsi_period: int | None = None              # None=不过滤
rsi_max: float | None = None               # RSI高于此值不进场(防追高,如75)
```

### 1b. `StrategySizing` 新增字段
```python
equity_basis: Literal["cash", "equity"] = "cash"       # risk_percent的基数
min_position_value_pct: float | None = None            # 仓位占基数最低比例(如5%)
```

### 1c. 新增 `TradingCosts` 数据类(手续费/滑点,第3点)
```python
@dataclass
class TradingCosts:
    commission_bps: float = 0.0    # 单边佣金(bps)
    slippage_bps: float = 0.0      # 单边滑点(bps)
```
挂到 `TradingStrategy.costs: TradingCosts | None = None`(默认None=旧行为无成本)。

### 1d. `parse_strategy` / `_parse_leveraged_breakout_pullback` / `_parse_sizing` 扩展
- 读取上述新字段,做基本校验(percentile∈(0,100]、mult>0、rsi_max∈(0,100)等)。

## Phase 2 — 仓位 sizing 重构 (`paper_trading.py`,第1点 P0)

`_quantity_from_signal` 的 `risk_percent` 分支改为:
1. 基数 = `equity` 时取 `cash + 持仓市值`;`cash` 时取现金(旧行为)。需要一个 `store.get_equity(currency, last_price)` 辅助(复用 backtest 的 `_equity_by_currency` 逻辑,抽到 store 或传入)。
2. `risk_cash = base × amount%`(amount=2.0 → 2% 的**总权益**)。
3. `risk_quantity = risk_cash // risk_per_share`。
4. 若配了 `min_position_value_pct`:计算 `min_qty = floor(base × pct% / price)`,取 `max(risk_quantity, min_qty)`,但仍受 `cash_quantity`(可用现金)和 `max_position_amount` 上限约束。
5. 成本应用:买入价 = `price × (1 + slippage_bps/1e4)`;佣金从现金额外扣除(见 Phase 3)。

**预期效果**:宽止损时仓位不再线性缩到接近0,能显著缩小与 buy-hold 的差距。

## Phase 3 — 回测真实性:手续费/滑点 + 次根成交 (P0-3, P0-4)

### 3a. 成本应用到成交价 (`paper_trading.py` `_buy`/`_sell`)
- 买入成交价 = `quote_price × (1 + slippage_bps/1e4)`;卖出 = `quote_price × (1 - slippage_bps/1e4)`。
- 佣金 = `amount × commission_bps/1e4`,从现金扣除(买多扣、卖少收)。
- `OrderExecution.price` 记录实际成交价(含滑点);新增 `metadata` 记佣金便于统计。
- `PaperBroker.__init__` 增加 `costs: TradingCosts | None`,默认 None=无成本(向后兼容)。

### 3b. 次根成交 (next-bar execution, `backtest.py`)
回测主循环改为**延迟一拍**执行:
```
pending = []
for quote in quotes:
    # 先用本根(T)价格执行上一根产生的挂单
    for sig in pending: execute(sig) at quote.price; engine.mark_filled(...)
    pending = []
    # 再生成本根信号(下根执行)
    pending = engine.generate_signals([quote])
# 收尾:最后一根的挂单按最后收盘价执行(或标记未成交)
```
**关键正确性修复**:引擎需在信号产生但尚未成交期间**禁止重复发入场信号**(当前仅靠 `active_position` 判断,延迟成交会导致重复触发)。在 `_leveraged_states` 增加 `pending_entry` 标志:发买入信号时置 True,`mark_filled` FILLED 买入时清 False;有 pending_entry 时不再产生新入场信号。
- 新增回测选项 `next_bar_execution: bool`(CLI `--next-bar` / `--same-bar`,默认 next-bar 更真实,可关回旧行为)。

## Phase 4 — 时间尺度一致性 (P0-2)
- `LeveragedBreakoutPullbackSetup` 增加信息性字段 `bar_timeframe: str = "unknown"`(如 "daily"/"30m")。
- `strategies.yaml` 配置里显式标注 `bar_timeframe: "daily"` 并加注释说明 `lookback_bars`/`trend_*_bars` 的单位。
- `parse_strategy` 校验:若 `bar_timeframe` 与回测 `--source` 语义明显冲突(如标 daily 却跑 30m 快照)→ 打 warning 日志(不报错)。

## Phase 5 — 分级止损 + 时间止损 + 止损后冷却 (`strategy_engine.py`,P1-5/10)

`_generate_leveraged_exit_signal` 增强:
- **持仓bar计数**:position 增加 `bars_held`,每根 +1。
- **分级止损**:`partial_taken` 后,若设了 `trailing_stop_pct_after_partial`,trailing 用更紧的百分比(如 22%→11%)。
- **时间止损**:若 `bars_held >= time_stop_bars` 且未到 1R 浮盈 → 发 `time_stop` 卖出信号(exit_kind=final)。
- **止损后冷却**:最终止损离场时记录 `last_stop_time`;入场前检查 `now - last_stop_time < cooldown_after_stop_minutes×60` → 拒绝入场。

---

## Phase 6 — 市场状态/量/RSI 过滤 (`strategy_engine.py`,P1-7/8/9)

新增辅助方法(均基于 close+volume 历史):
- `_percentile_resistance(prices, lookback, pct)`:替代裸 `max`,用百分位忽略尖峰(第8点)。
- `_avg_volume(volumes, period)` / 突破bar量比检查(第7点):`waiting_breakout→waiting_pullback` 转换时,若 `require_volume_confirm` 且当根量 < 均量×mult → 不确认突破。
- `_rsi(prices, period)` Wilder RSI(第7点):入场前若 `rsi_period` 配置且 RSI > `rsi_max` → 不进场。
- **连续收盘确认**(第9点):`waiting_confirmation` 阶段,若 `require_close_above_resistance_bars > 1`,累计满足条件的bar数,达到才发买入信号。

所有过滤默认关闭/取保守值,老配置行为不变。

## Phase 7 — 风险调整指标 + 诚实胜率 (`backtest.py`,P2-12 / P1-6)

`run_backtest` summary 与 `write_markdown_report` 新增:
- **Sharpe / Sortino**(按日收益率,年化系数随 source:日线=252)。
- **Calmar** = 年化收益 / |最大回撤|。
- **最大回撤恢复时间**(bars)。
- **平均R倍数** = 每笔卖出的 (realized_pnl / 计划risk_amount),需在 trade 记录里带上入场时的 risk_per_share。
- **盈亏比 / 期望收益**。
- **MAE/MFE 回吐比**:每笔交易的最大浮盈 vs 最终实现(用 equity_curve 逐bar跟踪未实现),揭露"100%胜率"背后的利润回吐。新增 trade 字段 `max_favorable_excursion`、`give_back_pct`。
- **公平基准**:同时输出"半仓 buy-hold"收益作为更公平对比(因为策略实际仓位远小于满仓)。

## Phase 8 — Walk-forward 验证 (`backtest.py`,P2-11)

新增 `run_walk_forward(db_path, strategies, accounts, train_months, test_months, ...)`:把全期切成滚动 train/test 窗口,在每个窗口跑 `run_backtest`,汇总**样本外**结果(收益、回撤、胜率、Sharpe)。
- CLI: `python -m src.backtest walk-forward --train-months 12 --test-months 3 ...`(或 `--walk-forward` 子命令)。
- 输出一份汇总 markdown,标注哪些窗口样本外为负 → 暴露过拟合。

## 执行顺序与提交粒度
按 Phase 1→10 顺序实现,每个 Phase 结束跑一次 `pytest` 确保全绿,形成可独立验证的提交点。Phase 3(次根成交)与 Phase 5/6(引擎逻辑)有交叉,会一起调整引擎状态结构,放在相邻提交。

## 风险与回退
- 所有新字段默认值 = 旧行为,任何 Phase 出问题都可单独回退。
- 次根成交默认开启会改变历史回测数字 → before/after 报告会明确对比,不覆盖旧报告文件。
- 参数默认值是经验值,最终以 Phase 9b 回测为准调整,不擅自锁定"最优"。
